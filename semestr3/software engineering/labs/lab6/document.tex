    \textbf{\underline{Тема:}} «Породжувальні шаблони. Шаблони Prototype, Singleton, Factory Method, Abstract Factory, Builder».

    \vspace{1em}

    \textbf{\underline{Мета:}} Вивчення шаблонів поведінки. Отримання базових навичок з застосування
шаблонів Prototype, Singleton, Factory Method Abstract Factory та Builder.

    \begin{center} \textbf{\Large Практична частина (Завдання №1)} \end{center}

    \setlength{\parindent}{1.5em}

    Мій номер залікової книги: $4106$, звідси $4106 \text{ mod } 7 = 4$. Тому умова до 1 завдання буде:

    Необхідно створити модель для подання розпорядника гри (\texttt{GameManager}), 
    який складається з ігрового простору та списку ігрових фішок. 
    Потрібно забезпечити можливість створення \textbf{тільки одного примірника} 
    розпорядника за допомогою шаблону \textit{Singleton}.

    \subsection*{Вимоги}

    \begin{itemize}
        \item \textbf{Клас розпорядника гри (\texttt{GameManager}):}
        \begin{itemize}
            \item має бути єдиною точкою керування грою;
            \item повинен зберігати стан ігрового простору 
            (наприклад, поле, карта, рівень);
            \item повинен містити список ігрових фішок 
            (об’єкти, які представляють гравців або елементи гри);
            \item має забезпечувати методи для додавання, видалення 
            та оновлення фішок;
            \item має містити метод для запуску або перезапуску гри.
        \end{itemize}

        \item \textbf{Гарантія єдиного примірника:}
        \begin{itemize}
            \item якщо інші частини програми спробують створити новий об’єкт 
            \texttt{GameManager}, це повинно бути неможливо;
            \item усі звернення до розпорядника гри мають здійснюватися 
            лише через уже існуючий примірник.
        \end{itemize}

        \item \textbf{Допоміжні класи (за бажанням для зручності):}
        \begin{itemize}
            \item \texttt{GameSpace} --- описує ігрове поле або середовище;
            \item \texttt{GamePiece} --- представляє окрему ігрову фішку 
            (позиція, тип, стан).
        \end{itemize}

        \item \textbf{Загальна структура системи:}
        \begin{itemize}
            \item система повинна бути спроєктована так, щоб усі елементи гри 
            взаємодіяли між собою \textbf{через} \texttt{GameManager}.
        \end{itemize}
    \end{itemize}

    \subsection*{У методі \texttt{main} продемонструвати:}

    \begin{itemize}
        \item створення кількох «об’єктів» \texttt{GameManager} і показати, 
        що в усіх випадках повертається один і той самий екземпляр 
        (робота шаблону \textit{Singleton});
        \item додавання кількох ігрових фішок у спільний ігровий простір 
        через \texttt{GameManager};
        \item виведення поточного стану гри 
        (наприклад, параметри простору та список фішок);
        \item підтвердити, що зміни, внесені через один доступ 
        до \texttt{GameManager}, відображаються при зверненні до нього 
        з будь-якої іншої частини програми.
    \end{itemize}

    \begin{center} \textbf{\Large Практична частина (Завдання №2)} \end{center}

    Мій номер залікової книги: $4106$, звідси $4106 \text{ mod } 7 = 4$. Тому умова до 2 завдання буде:

    Необхідно визначити специфікації класів для подання сімейства інструментів
    універсального інтегрованого середовища розробки
    (\texttt{Validator}, \texttt{Compiler}, \texttt{Debugger}) з їх реалізацією
    для різних мов (\texttt{Java}, \texttt{C++}).

    \subsection*{Вимоги}

    \begin{itemize}
        \item \textbf{Фабрика інструментів середовища розробки:}
        \begin{itemize}
            \item створити абстрактний клас або інтерфейс \texttt{IDEToolsFactory},
            який визначає фабричні методи для створення компонентів середовища
            розробки:

            \texttt{createValidator()}~-- повертає об’єкт для перевірки коду,
            \texttt{createCompiler()}~-- повертає об’єкт компілятора,
            \texttt{createDebugger()}~-- повертає об’єкт дебагера;
            \item класи \texttt{JavaIDEToolsFactory} та \texttt{CppIDEToolsFactory}
            є конкретними реалізаціями \texttt{IDEToolsFactory}, що створюють
            інструменти для відповідних мов програмування.
        \end{itemize}

        \item \textbf{Інтерфейси інструментів:}
        \begin{itemize}
            \item створити абстрактні інтерфейси \texttt{Validator},
            \texttt{Compiler} та \texttt{Debugger}, які визначають базові методи роботи,
            наприклад:
            \texttt{validateCode(String code)} для \texttt{Validator},
            \texttt{compile(String source)} для \texttt{Compiler},
            \texttt{debug(String program)} для \texttt{Debugger}.
        \end{itemize}

        \item \textbf{Реалізації для мов програмування:}
        \begin{itemize}
            \item класи \texttt{JavaValidator}, \texttt{JavaCompiler},
            \texttt{JavaDebugger}~-- реалізації інтерфейсів для мови Java;
            \item класи \texttt{CppValidator}, \texttt{CppCompiler},
            \texttt{CppDebugger}~-- реалізації інтерфейсів для мови C++.
        \end{itemize}

        \item \textbf{Розширюваність системи:}
        \begin{itemize}
            \item забезпечити можливість прозорого для клієнта розширення системи
            новими реалізаціями для інших мов без зміни клієнтського коду.
        \end{itemize}
    \end{itemize}

    \subsection*{У методі \texttt{main} продемонструвати:}

    \begin{itemize}
        \item створення фабрики певного типу (наприклад,
        \texttt{JavaIDEToolsFactory} або \texttt{CppIDEToolsFactory});
        \item за допомогою фабрики створити об’єкти всіх компонентів:
        \texttt{Validator}, \texttt{Compiler} і \texttt{Debugger};
        \item виклик відповідних методів для перевірки, компіляції
        та відладки умовного фрагмента коду.
    \end{itemize}

    \textbf{\underline{Висновок:}} У ході виконання роботи було спроєктовано та реалізовано модель
сімейства інструментів інтегрованого середовища розробки (IDE),
що включає компоненти \texttt{Validator}, \texttt{Compiler} та
\texttt{Debugger} для двох мов програмування --- Java та C++.
Для створення взаємопов'язаних об'єктів цих типів було застосовано
шаблон проєктування \textit{Abstract Factory} у вигляді інтерфейсу
\texttt{IDEToolsFactory} та його конкретних реалізацій
\texttt{JavaIDEToolsFactory} і \texttt{CppIDEToolsFactory}.
Клієнтський код (\texttt{IDEToolsDemo}) працює виключно з абстракціями
фабрики та інтерфейсами інструментів, що демонструє ослаблене
зв'язування між використанням інструментів і їх конкретними реалізаціями.

Результати запуску програми показали коректність роботи фабрик:
для кожного типу фабрики створюється узгоджений набір інструментів
(валідатор, компілятор, налагоджувач), над якими послідовно виконуються
операції перевірки коду, компіляції та налагодження. Завдяки такій
організації системи стає можливим прозоре розширення: для додавання
підтримки нової мови достатньо реалізувати нові класи-продукти
(\texttt{XxxValidator}, \texttt{XxxCompiler}, \texttt{XxxDebugger})
та відповідну фабрику \texttt{XxxIDEToolsFactory}, не змінюючи клієнтський код.

Таким чином, мету роботи досягнуто: розроблено узагальнену структуру
IDE-інструментів із використанням шаблону \textit{Abstract Factory},
продемонстровано переваги інкапсуляції способів створення об'єктів
і забезпечено розширюваність програмної системи без модифікації
існуючого клієнтського коду.
