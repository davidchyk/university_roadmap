    \noindent
    Мій порядковий номер у списку групи: 6, звідси я маю реалізувати такий алгоритм сортування: \underline{Порозрядне сортування}, алгоритмічна складність якого $O(nk)$, де $k$ -- кількість розрядів (для десяткової системи числення, це максимальна кількість цифр серед чисел), $n$ -- розмір масиву (кількість чисел).
    Наведемо блок-схему алгоритму порозрядного сортування:

        \centering

    \noindent
    Потрібні до цього алгоритму уточнення та коментарі: 

    \vspace{1em}

    У побудованому алгоритмі використано допоміжні процеси $\max(A)$

    та

    $\texttt{counting\_sort}(A, exp)$, які доцільно окремо пояснити.

    \paragraph{Процес $\max(A)$.}
    Операція $\max(A)$ означає пошук максимального елемента масиву $A$.
    Цей процес потрібен для того, щоб визначити, скільки розрядів має найбільше число масиву, а отже --- скільки проходів порозрядного сортування необхідно виконати.

    Наприклад, якщо найбільший елемент масиву дорівнює $802$, то він має $3$ розряди.
    Отже, алгоритм має виконати $3$ проходи:
    \begin{enumerate}
        \item за розрядом одиниць;
        \item за розрядом десятків;
        \item за розрядом сотень.
    \end{enumerate}

    У програмній реалізації після знаходження максимального елемента використовується умова
    \[
    \texttt{max\_num // exp > 0},
    \]
    яка перевіряє, чи залишився ще необроблений розряд.

    \paragraph{Процес $\texttt{counting\_sort}(A, exp)$.}
    Процес $\texttt{counting\_sort}(A, exp)$ означає сортування підрахунком за поточним розрядом.
    Це допоміжна процедура, яка впорядковує елементи масиву не за всім числом повністю, а лише за однією цифрою, що визначається значенням $exp$.

    Поточна цифра обчислюється за формулою
    \[
    \texttt{digit = (num // exp) \% 10}.
    \]

    При цьому:
    \begin{itemize}
        \item якщо $exp = 1$, отримуємо цифру одиниць;
        \item якщо $exp = 10$, отримуємо цифру десятків;
        \item якщо $exp = 100$, отримуємо цифру сотень.
    \end{itemize}

    \paragraph{Суть сортування підрахунком у цьому алгоритмі.}
    Сортування підрахунком виконується у кілька етапів:
    \begin{enumerate}
        \item для кожного елемента масиву визначається цифра поточного розряду;
        \item підраховується, скільки разів зустрічається кожне можливе значення цифри від $0$ до $9$;
        \item на основі отриманих підрахунків формується масив позицій;
        \item елементи розміщуються у допоміжному масиві у правильному порядку;
        \item після цього результат копіюється назад у вихідний масив.
    \end{enumerate}

    Оскільки в десятковій системі числення можливі лише $10$ цифр $(0,1,\dots,9)$, для підрахунку використовується допоміжний масив довжини $10$.

    \paragraph{Чому саме сортування підрахунком використовується в Radix Sort.}
    У порозрядному сортуванні важливо, щоб сортування за кожним окремим розрядом було стабільним, тобто щоб елементи з однаковим значенням поточного розряду зберігали свій попередній відносний порядок.
    Саме тому сортування підрахунком добре підходить для реалізації Radix Sort.

from __future__ import annotations

def radix_sort(arr: list[int]) -> tuple[list[int], int]:
    ops = 0

    ops += 1  # перевірка if not arr
    if not arr:
        ops += 1  # return
        return arr, ops

    max_num = max(arr)
    ops += len(arr)  # пошук максимуму = n операцій

    exp = 1
    ops += 1  # присвоєння

    ops += 1  # перша перевірка while
    while max_num // exp > 0:
        ops += 1  # обчислення max_num // exp > 0

        _, sub_ops = counting_sort_by_digit(arr, exp)
        ops += sub_ops

        exp *= 10
        ops += 1  # множення + присвоєння

        ops += 1  # наступна перевірка while

    ops += 1  # return
    return arr, ops

def counting_sort_by_digit(arr: list[int], exp: int) -> tuple[list[int], int]:
    ops = 0

    n = len(arr)
    ops += 1

    output = [0] * n
    ops += n  # створення масиву довжини n

    count = [0] * 10
    ops += 10  # створення масиву довжини 10

    # Підрахунок цифр
    for num in arr:
        ops += 1  # ітерація циклу
        digit = (num // exp) % 10
        ops += 2  # // і %
        count[digit] += 1
        ops += 1  # інкремент

    ops += 1  # завершальна перевірка циклу

    # Префіксні суми
    for i in range(1, 10):
        ops += 1  # ітерація циклу
        count[i] += count[i - 1]
        ops += 2  # індексація + додавання

    ops += 1  # завершальна перевірка циклу

    # Побудова output справа наліво
    for i in range(n - 1, -1, -1):
        ops += 1  # ітерація циклу
        digit = (arr[i] // exp) % 10
        ops += 3  # arr[i], //, %
        output[count[digit] - 1] = arr[i]
        ops += 3  # count[digit], -1, присвоєння
        count[digit] -= 1
        ops += 2  # доступ + декремент

    ops += 1  # завершальна перевірка циклу

    # Копіювання назад
    for i in range(n):
        ops += 1  # ітерація циклу
        arr[i] = output[i]
        ops += 2  # читання + присвоєння

    ops += 1  # завершальна перевірка циклу

    ops += 1  # return
    return arr, ops
    \end{minted}

from __future__ import annotations

import random
from collections.abc import Callable

from matplotlib.figure import Figure


def build_actual_vs_theoretical_figure(
    sort_func: Callable[[list[int]], tuple[list[int], int]]
) -> Figure:
    sizes: list[int] = []
    actual_ops: list[int] = []
    theoretical_ops: list[int] = []

    d = 4
    k = 10

    for n in range(10, 501, 10):
        arr = [random.randint(0, 9999) for _ in range(n)]
        _, ops = sort_func(arr.copy())

        sizes.append(n)
        actual_ops.append(ops)
        theoretical_ops.append(d * (n + k))

    scale = actual_ops[-1] / theoretical_ops[-1]
    theoretical_scaled: list[float] = [x * scale for x in theoretical_ops]

    fig = Figure(figsize=(9, 6), dpi=100)
    ax = fig.add_subplot(111)

    ax.plot(sizes, actual_ops, marker="o", label="Фактична кількість операцій")
    ax.plot(
        sizes,
        theoretical_scaled,
        linestyle="--",
        label="Теоретична залежність d(n+k)",
    )

    ax.set_xlabel("Розмір масиву n")
    ax.set_ylabel("Кількість операцій")
    ax.set_title("Порівняння фактичної та теоретичної залежностей для Radix Sort")
    ax.grid(True)
    ax.legend()

    fig.tight_layout()
    return fig

INT_LIST_SPLIT_PATTERN = re.compile(r"[,\s]+")


@dataclass(frozen=True)
class PageConfig:
    page_id: str
    nav_title: str
    title: str
    subtitle: str


def parse_int_array(raw: str) -> list[int]:
    value = raw.strip()
    if not value:
        raise ValueError("Поле масиву не може бути порожнім")

    parts = [part for part in INT_LIST_SPLIT_PATTERN.split(value) if part]
    if not parts:
        raise ValueError("Не вдалося розпізнати жодного числа")

    try:
        return [int(part) for part in parts]
    except ValueError as exc:
        raise ValueError(
            "Масив має містити лише цілі числа, розділені пробілами або комами"
        ) from exc

    def load_json(self) -> None:
        path = filedialog.askopenfilename(
            title="Select JSON file",
            filetypes=[("JSON files", "*.json"), ("All files", "*.*")],
        )
        if not path:
            return

        try:
            raw_data = Path(path).read_text(encoding="utf-8")
            loaded = json.loads(raw_data)

            if not isinstance(loaded, dict):
                raise ValueError("JSON root must be an object")

            if "array" not in loaded:
                raise ValueError("JSON must contain key 'array'")

            array_data = loaded["array"]

            if not isinstance(array_data, list):
                raise TypeError("'array' must be a list")

            if not all(isinstance(x, int) for x in array_data):
                raise TypeError("'array' must contain only integers")

            prepared = ", ".join(str(x) for x in array_data)

            self.array_entry.delete(0, tk.END)
            self.array_entry.insert(0, prepared)

            self.result_var.set("JSON loaded. Press Sort.")
            self.error_var.set("")
        except Exception as exc:
            self.result_var.set("No result")
            self.error_var.set(f"Error: {exc}")

    def compute(self) -> None:
        try:
            raw = self.array_entry.get()
            arr = parse_int_array(raw)
            sorted_arr, ops = self.sort_func(arr.copy())

            self.result_var.set(f"Sorted array: {sorted_arr}\nOperations: {ops}")
            self.error_var.set("")
        except Exception as exc:
            self.result_var.set("No result")
            self.error_var.set(f"Error: {exc}")

    def clear_all(self) -> None:
        self.array_entry.delete(0, tk.END)
        self.result_var.set("Ready")
        self.error_var.set("")

    \begin{itemize}
        \item GUI побудовано на \texttt{customtkinter} у мінімалістичному стилі з темною кольоровою схемою.
        \item Програма містить 2 основні сторінки: \texttt{Sort} та \texttt{Graph}.
        \item Сторінка \texttt{Sort} призначена для введення масиву цілих чисел, виконання порозрядного сортування та виведення відсортованого масиву разом із кількістю виконаних операцій.
        \item Ввід масиву підтримується як вручну через поле введення, так і шляхом завантаження JSON-файлу.
        \item Для сторінки \texttt{Sort} передбачено кнопки \texttt{Sort}, \texttt{Load JSON} та \texttt{Clear}.
        \item JSON завантажується з файлу, при цьому очікується структура вигляду \texttt{\{"array": [170, 45, 75, 90, 802, 24, 2, 66]\}}.
        \item Під час завантаження JSON виконується перевірка, що кореневий елемент є об'єктом, що існує ключ \texttt{array}, що його значення є списком, а всі елементи списку є цілими числами.
        \item Сторінка \texttt{Graph} призначена для побудови графіка фактичної кількості операцій та теоретичної залежності алгоритму порозрядного сортування.
        \item Графік не відкривається в окремому вікні, а вбудовується безпосередньо в інтерфейс програми за допомогою \texttt{FigureCanvasTkAgg}.
        \item Для сторінки \texttt{Graph} передбачено кнопку \texttt{Build Graph}, яка викликає побудову графіка на основі функції сортування.
        \item У програмі реалізовано окремі блоки для відображення результату, статусу виконання та повідомлень про помилки.
        \item Помилки не зупиняють виконання програми, а відображаються в інтерфейсі у форматі \texttt{Error: ...}.
        \item Навігація між сторінками виконується через верхню панель перемикання вкладок.
    \end{itemize}

    \begin{center} \textbf{\large Аналіз результатів} \end{center}

    У ході виконання роботи було реалізовано алгоритм порозрядного сортування (\texttt{Radix Sort}) для масиву цілих невід'ємних чисел, а також програмний модуль для побудови графічної залежності фактичної кількості операцій від розміру вхідного масиву та її порівняння з теоретичною оцінкою.

    У результаті тестування встановлено, що алгоритм коректно впорядковує елементи масиву за зростанням. Робота алгоритму ґрунтується на послідовному сортуванні елементів за окремими розрядами числа, починаючи з молодшого розряду і закінчуючи старшим. Для кожного розряду використовується стабільне сортування підрахунком, що забезпечує збереження відносного порядку елементів із однаковими значеннями поточної цифри.

    Під час експериментального дослідження було виконано підрахунок кількості операцій, які здійснює алгоритм при сортуванні масивів різної довжини. На основі отриманих значень побудовано графік фактичної кількості операцій. Також було побудовано теоретичну залежність, що відповідає часовій складності алгоритму порозрядного сортування.

    Аналіз графіка показує, що зі збільшенням кількості елементів масиву кількість операцій зростає майже лінійно. Це узгоджується з теоретичною оцінкою складності алгоритму. Для порозрядного сортування часова складність часто подається у вигляді
    \[
    O(nk),
    \]
    де $n$ --- кількість елементів масиву, а $k$ --- кількість розрядів у найбільшому числі. У більш детальному вигляді цю складність можна записати як
    \[
    O(k(n+b)),
    \]
    де $k$ --- кількість розрядів, а $b$ --- основа системи числення. У даній реалізації використовується десяткова система числення, тому $b=10$ є сталою, а отже складність можна розглядати як лінійну за $n$ при фіксованому числі розрядів.

    Крім часової складності, було проаналізовано й витрати пам'яті. Алгоритм використовує допоміжний масив \texttt{output} розміру $n$ та масив підрахунків \texttt{count} розміру $10$, тому просторова складність становить
    \[
    O(n + 10) = O(n).
    \]

    Отримані результати підтверджують, що порозрядне сортування є ефективним для сортування цілих чисел, особливо у випадках, коли кількість розрядів у числах є відносно невеликою. Побудований графік демонструє відповідність між практичними результатами підрахунку операцій та теоретичною оцінкою складності, що підтверджує коректність реалізації алгоритму та правильність виконаного аналізу.
